### 공통 입력 네트워크

- `graph_cache.pkl`
    - `네트워크데이터셋_DiGraph_변환_gpkg_pkl.py`의 출력물
    - GeoPackage → NetworkX DiGraph 변환 → degree-2 체인 축약 적용
    - CRS: EPSG:5179
    - payload 구조: `{ graph, crs_epsg, node_round_m, source_gpkg, source_layer, contracted, original_nodes, original_edges }`
    - `contracted: True`는 축약이 적용된 그래프임을 표시
    - `original_nodes`, `original_edges`는 축약 전 원본 그래프의 노드·간선 수
    - 로딩 시 fallback: payload가 dict이면 `payload["graph"]` 추출, 그렇지 않으면 객체 자체를 DiGraph로 사용

### 그래프 축약 (Degree-2 체인 축약)

DiGraph 생성 후 `contract_degree2()` 함수를 적용하여 그래프를 축약한다. in_degree=2, out_degree=2이고 predecessors==successors인 노드(degree-2 체인 노드)를 제거하고, 인접 간선을 병합한다. 비용은 합산, geometry는 연결한다.

축약 간선에는 다음 속성이 추가 저장된다:

- `chain_nodes`: 원본 노드 순서열 (축약 전 체인 경로). 예: [start, mid1, mid2, end]
- `chain_costs`: 구간별 비용 딕셔너리 리스트. 예: [{length_3dkm: 0.03, hour_ks: ...}, ...]

이 정보는 간선 분할(edge split) 시 비용의 정확한 선형 보간에 사용된다. 비축약 간선(chain 미포함)에서는 `chain_nodes`와 `chain_costs`가 생략되며, 분할 시 [u, v]와 단일 비용으로 처리된다.

> 축약에 의해 그래프의 노드·간선 수가 대폭 감소하여 메모리 사용량과 경로 탐색 성능이 개선된다. 축약 전후의 경로 비용은 수학적으로 동일하다.
>

### 좌표 스냅 (간선 기반)

입력 좌표(EPSG:4326)를 EPSG:5179로 변환한 후, 최근접 간선에 투영하여 그래프 노드에 스냅한다. 절차는 다음과 같다:

1. 그래프의 전체 간선을 GeoDataFrame(`edge_gdf`)으로 구성하여 공간 인덱스를 생성
2. 입력 좌표에서 최근접 간선을 탐색하고, 간선 geometry 위의 투영점을 계산
3. 투영점이 기존 노드(간선의 시작·끝 노드)의 허용 거리(15 m) 이내이면 해당 기존 노드를 반환
4. 투영점이 간선 내부에 위치하면 임시 노드를 삽입하고 간선을 분할

간선 분할 구성:

- `snap_to_graph(x, y, edge_gdf, G)` → 최근접 간선 탐색, 투영, 임시 노드 삽입 또는 기존 노드 반환
- `_split_edge(G, u, v, temp_node, d)` → 정방향·역방향 간선을 동시에 분할
- `_interpolate_split(edge_geom, chain_nodes, chain_costs, d, cost_keys)` → 축약 간선의 `chain_nodes`/`chain_costs`를 기반으로 세그먼트별 비용을 선형 보간, geometry는 Shapely `substring`으로 분할
- `restore_splits(G, infos)` → 분석 완료 후 임시 노드와 분할 간선을 제거하고 원본 간선을 복원

`restore_splits`에 의해 동일 그래프 객체를 복수의 경로 분석에 재사용할 수 있다. 스냅 거리는 출력 속성(`snap_m_start`, `snap_m_end` / `snap_m_last`)에 기록된다.

> 축약 그래프에서 간선이 다수의 원본 세그먼트를 병합하고 있으므로, 투영점이 간선 내부에 위치할 때 `chain_costs`를 기반으로 정확한 비용 분할이 필요하다. `_interpolate_split`은 투영 거리(d)가 해당하는 세그먼트를 식별하고, 해당 세그먼트 내에서의 비율에 따라 5개 비용 필드를 각각 보간한다.
>

### 목표값 입력 방식 (beg / end 2컬럼)

전 분석(섹션 2·3·8·9)은 목표값을 단일 컬럼이 아닌 **beg·end 2컬럼**으로 입력받는다. 거리 모드는 `km_beg, km_end`, 시간 모드는 `hr_beg, hr_end`이며, 하위 호환(`target_km`/`target_hr` 단일 컬럼)은 지원하지 않는다. 행별 분기는 다음과 같다.

- `beg`만 입력(`end` 빈칸) → **단일 목표값 모드** (T = beg, `min|비용 − T|` 근접)
- `beg`·`end` 모두 입력 → **구간 모드** [beg, end]
- `beg` 빈칸 → **미입력** (기본 분석은 route_min_*만 산출하고 route_target 생략, 순위·편차범위 분석은 해당 행 건너뜀)
- `beg > end` 또는 `end`만 입력(`beg` 빈칸) → **오류**로 해당 행 건너뜀(콘솔 보고)

> 미입력(beg 빈칸) 시 route_target의 `abs_diff`와 `km_beg`/`km_end`(`hr_beg`/`hr_end`)는 NULL로 저장된다. 단일 모드 시 `km_end`/`hr_end`는 NULL이다.

## 2. 포인트-포인트 분석


- 장애물 GPKG (선택 입력)
    - line 장애물: LineString 또는 MultiLineString geometry만 허용
    - polygon 장애물: Polygon 또는 MultiPolygon geometry만 허용
    - CRS 자동 변환 → EPSG:5179
    - 장애물과 교차하는 간선을 그래프에서 제거(완전 차단)하여 경로 탐색에서 배제

### 최소 경로 (route_min_*)

- 각 임피던스별로 독립 계산
- 대상 임피던스:
    - `length_3dkm`
    - `hour_ks`
    - `hour_tob`
    - `kcal_ks`
    - `kcal_tob`
- 각 leg에 대해 최단경로(`shortest_path_leg`) 수행
- leg별 경로를 연결하여 전체 경로 구성
- route_min_*는 목표값 입력과 무관하게(단일/구간/미입력 모두) 항상 산출

### 목표값 근접/구간 경로 (route_target)

route_target은 행의 입력 형식에 따라 **단일 목표값 모드** 또는 **구간 모드**로 분기한다.

**[단일 목표값 모드] (`end` 빈칸, T = beg) — 원본 목표값 근접 분석 (`min|비용 − T|`)**

*단일 구간(경유지 없음):* 후보 생성은 2단계 확장 방식으로 운영된다.

1. 1차 단계: 최대 `K_INIT=10`개의 후보를 오름차순으로 수집하되, 목표값 이상 후보가 나타나면 해당 후보까지 포함하고 조기 종료
2. 목표값 이상 후보가 확보되지 않으면 `K_MAX=30,000`까지 확장
3. 후보 중 |비용 − 목표값| 최소인 경로 선택

*경유지가 있는 경우(leg 2개 이상):* T_j 상한 사전 생성과 bisect 탐색을 결합한 방식으로 최적 조합을 선택한다.

1. 각 구간에 대해 최단 경로를 산출하여 구간별 최소 비용(min_j)과 전체 최소합 S_min = Σmin_j를 확보
2. T_j 상한 계산: 각 leg j에 대해 유효 상한 T_j = T − (S_min − min_j)를 산출
3. 후보 생성은 구간 수에 따라 달라진다. 구간이 3개 이상인 경우 각 구간의 후보를 T_j 상한까지 사전 생성한다(T_j 초과 후보 1개 포함 시점까지, `K_MAX`는 안전 상한). 구간이 2개인 경우 T_j가 작은 구간만 사전 생성하고, T_j가 큰 구간은 K-shortest simple paths를 지연 열거한다
4. 조합 탐색:
   - **2-leg (경유지 1개):** T_j가 작은 구간을 bisect, T_j가 큰 구간을 lazy iterate로 할당. iterate 구간의 후보를 순차적으로 꺼내며 bisect 구간의 정렬 배열에 이진 탐색을 수행하여 잔여 예산(T − c_iterate)에 가장 근접하는 직전·직후 후보를 O(log K_bisect)에 결정. 종료: c_iterate + min(bisect 구간) − T ≥ best_diff, 또는 iterate 구간이 T_j 상한·K_MAX 도달, 또는 best_diff < 1e-4
   - **3-leg 이상 (경유지 2개 이상):** 앞쪽 N−1개 leg을 min-heap으로 조합 탐색하고, 마지막 leg은 bisect로 최적 매칭. 종료 조건은 2-leg과 동일 원리이며 best_diff < 1e-4 조기 종료도 적용

> 기본 분석의 2-leg 역할 분담은 "T_j 작은 구간 bisect" 규칙으로 고정된다(순위·편차범위 분석의 probe 진단은 적용하지 않음).
> 

**[구간 모드] (`beg`·`end` 모두 입력) — 선택 임피던스의 최소비용경로 1개**

선택 임피던스(거리: `length_3dkm`, 시간: 선택값)의 최소비용경로를 산출한다(`choose_target_interval_basic`). 그 metric이 [beg, end] 안이면 그 경로가 곧 구간 내 목표값 최적이므로 1개로 확정한다. 밖이면(최소가 end 초과 등) 그 최소경로를 fallback으로 출력한다. abs_diff = max(0, beg − metric, metric − end)(구간 내부는 0).

> 구간 내 대안 경로를 여러 개 탐색하려면 순위 분석(`_순위.py`)을 사용한다.
>

### K_MAX 도달 경로의 해석 기준

격자형 도로 구조에서 K-shortest simple paths 열거가 K_MAX(30,000)에 도달할 때까지 목표값 전후 범위를 확보하지 못하는 경로가 존재할 수 있다. 이 경우 K_MAX 도달로 종료된 경로의 route_min_km(거리 최소 비용 경로)의 abs_diff가 사료 기록 불확실성 범위(±5리 = 2.25 km) 이내이면, route_min_km을 해당 경로의 대표 경로로 채택한다. 이는 최소 비용 경로 자체가 사료 기록에 부합하는 수준의 거리를 이미 가지므로, K-shortest 열거에 의한 추가 탐색 없이도 의미 있는 결과를 제공할 수 있다는 판단에 근거한다.

> 수학적 최적 보장을 훼손하는 조기 종료 방안(예: 시간 제한, beam width 제한)은 도입하지 않는다. K_MAX 도달까지 장시간 소요되는 경로는 야간·주말 배치 처리로 대응한다.
>

### 목적지 후보 노드

- 폴리곤 boundary와 교차하는 간선을 공간 인덱스로 탐색(`find_boundary_destination_nodes`)
- 간선 양 끝 노드의 폴리곤 내외 상태에 따라 다음과 같이 처리한다

**단조 진입 케이스 (시작 노드 외부, 끝 노드 내부)**

- 비축약 간선(DEM 셀 크기 단위): 끝 노드를 그대로 채택
- 축약 간선: chain_nodes를 시작 노드에서 끝 노드 방향으로 순회하여, 폴리곤 내부에 처음 진입하는 chain node를 탐색. 해당 chain node에서 축약 간선을 2분할(`_split_edge_at_chain_idx`)하고, 분할된 노드를 목적지 후보로 채택. 비용은 chain_costs 합산으로 정확히 분할되므로 보간 오차가 없음
- 첫 내부 chain node가 끝 노드(v) 자체이면 분할 없이 v를 채택

**관통 케이스 (시작·끝 노드 모두 외부, chain 중간이 폴리곤 내부 관통)**

- 폴리곤 내부에 분기점이 없는 도로 구간에서 축약 간선이 폴리곤을 가로질러 통과할 때 발생한다. 장애물 적용 시에는 축약 간선이 장애물 경계에서 분할되어 잔존 간선의 양 끝이 폴리곤 외부가 되는 경우에 발생 빈도가 증가한다
- chain_nodes의 중간 노드(양 끝 제외)를 순회하여 폴리곤 내부에 처음 진입하는 chain node를 탐색. 해당 chain node에서 축약 간선을 2분할하고, 분할된 노드를 목적지 후보로 채택
- 비축약 간선의 관통은 DEM 셀 크기 해상도상 구조적으로 발생 가능성이 매우 낮으며, 그래프 노드 수준에서 진입점을 정의할 수 없으므로 처리하지 않는다

**반대 방향 진입 케이스 (시작 노드 내부, 끝 노드 외부)**

- DiGraph에서 정방향과 역방향은 별도 간선으로 관리되므로, 해당 간선의 역방향 간선이 단조 진입 케이스로 자동 포착되어 처리된다

**완전 내부 케이스 (시작·끝 노드 모두 내부)**

- 양 끝이 모두 폴리곤 내부인 간선은 경로의 첫 진입 간선이 될 수 없으므로 별도 처리하지 않는다. 외부에서 해당 간선의 양 끝(u 또는 v)에 도달하는 경로는 반드시 다른 간선에서 경계를 먼저 넘으며, 그 간선이 위의 케이스들로 처리된다

**공통**

- 분할에 의해 삽입된 노드는 해당 경로 분석 완료 후 `restore_splits`로 복원

> 축약 간선은 다수의 원본 세그먼트를 병합하여 끝 노드가 폴리곤 경계에서 수백 m 이상 떨어질 수 있다. chain_node 분할에 의해 원본 해상도(DEM 셀 크기 단위)의 경계 진입 지점이 목적지 후보로 복원된다.
> 

> 역방향 간선 처리: 정방향과 역방향이 서로 다른 병렬 체인을 채택한 경우(방향 비대칭 비용에 의해), 분할 노드가 역방향 chain_nodes에 존재하지 않을 수 있다. 이 경우 역방향 간선은 분할하지 않고 원본 상태를 유지한다.
>

### 경계 후보 노드 사전 봉인 (깨끗한 첫 진입 경로)

최종 목적지 이전에 다른 경계 후보 노드를 경유하는 경로는 배제한다. 특정 목적지 후보 노드까지의 최단경로가 다른 후보 노드를 먼저 통과하여 폴리곤 내부에 진입한 후 다시 외부로 나와 최종 목적지에 도달하는 경우가 발생할 수 있는데, 이러한 경로는 실질적으로 폴리곤에 이미 진입한 경로이므로 사방경계 도달 경로로서 부적절하다.

목적지 후보 노드(dest_node)는 모두 폴리곤에 처음 진입하는 노드(내부 또는 경계상)이므로, "최종 목적지 이전에 다른 dest_node를 거치지 않음"은 곧 "해당 노드에서 폴리곤에 처음 진입함"과 동치이다. 이 조건은 사후 필터링이 아니라 사전 봉인으로 강제된다. 출발 노드를 제외한 모든 dest_node를 가린 읽기 전용 뷰(`nx.restricted_view`)에서 단일 Dijkstra를 수행하면 폴리곤 내부가 봉인되어, 어떤 경로도 다른 dest_node를 거쳐 진입할 수 없다. 각 목적지 후보의 경로는 이 뷰의 최단거리에 외부측 진입 간선을 더해 '깨끗한 첫 진입 경로'로 복원한다(`collect_clean_dest_candidates`). 깨끗한 진입 경로가 존재하지 않는 후보만 제외되며, 전역 최단경로가 다른 후보를 경유한다는 이유만으로 후보를 통째로 탈락시키지 않는다(우회하는 깨끗한 경로가 있으면 그 경로를 채택한다). 이 절차는 route_min_*와 route_target의 모든 경로 산출 지점(직접 탐색, 1차 패스, 마지막 leg 후보 수집)에 동일하게 적용된다.

> 봉인의 정당성: dest_node는 모두 첫 진입 노드이므로, 전체 dest_node를 가리면 외부 출발 노드에서 폴리곤 내부로 가는 모든 경로가 차단된다. 따라서 뷰에서 후보 A에 도달하는 경로는 A를 첫 진입점으로 하는 경로뿐이며, 이는 'A를 제외한 나머지 dest_node를 제거한 그래프에서의 최단경로'와 동일하다. 뷰는 간선 비용·geometry를 변형하지 않으므로 비용 정밀성에 영향이 없다.
> 

> route_min_*의 최적성 보존: 목적지 A까지의 최단경로가 목적지 B를 경유한다면, 최적 부분구조에 의해 cost(S→B) < cost(S→A)이다. 따라서 전체 후보 중 비용이 최소인 노드의 최단경로는 다른 후보 노드를 경유할 수 없으므로, 봉인 적용 후에도 최소 비용 경로의 결과는 변하지 않는다.
>

### 최소 경로 (route_min_*)

- 각 임피던스별로 독립 계산
- 대상 임피던스:
    - `length_3dkm`
    - `hour_ks`
    - `hour_tob`
    - `kcal_ks`
    - `kcal_tob`

**유효 좌표 1개 (출발점만):**

- 출발 노드에서 모든 후보 노드까지 봉인 뷰 단일 Dijkstra로 깨끗한 첫 진입 경로 산출
- 해당 임피던스 비용이 최소인 경로 선택

**유효 좌표 2개 이상 (경유지 존재):**

- 앞쪽 leg(출발점 → ... → 마지막 경유지): 각 구간을 해당 임피던스 최단경로로 연결
- 마지막 leg(마지막 경유지 → 폴리곤 후보 노드): 봉인 뷰에서 후보 노드별 깨끗한 진입 경로 중 해당 임피던스 비용이 최소인 경로 선택
- 전체 경로 = 앞쪽 leg + 마지막 leg 병합

### 목표값 근접/구간 경로 (route_target)

route_target은 행의 입력 형식에 따라 **단일 목표값 모드** 또는 **구간 모드**로 분기한다.

**[단일 목표값 모드] (`end` 빈칸, T = beg) — 원본 목표값 근접 (`min|비용 − T|`)**

*유효 좌표 1개 (출발점만):* 출발 노드에서 봉인 뷰로 모든 후보 노드까지 깨끗한 최단경로를 산출하고, |비용 − 목표값| 최소 경로를 선택한다.

*유효 좌표 2개 이상 (경유지 존재):*

1. 1차 패스: 앞쪽 legs의 구간별 최소 비용 + 마지막 leg에서 각 목적지 후보 노드까지의 깨끗한 최단 경로 비용을 산출하여 전체 최소합(S_min)을 확보
2. 앞쪽 legs: 앞쪽 구간이 2개 이상이면 각 구간의 후보를 T_j 상한까지 사전 생성한다(T_j 초과 후보 1개 포함 시점까지, `K_MAX`는 안전 상한). 앞쪽 구간이 1개이면 사전 생성하지 않고 K-shortest simple paths를 지연 열거한다
3. 마지막 leg(마지막 경유지 → 폴리곤 후보 노드):
    - 유효 상한(t_last)을 계산하고, 1차 패스에서 확보한 최소 비용이 t_last를 초과하는 후보 노드를 사전 제외
    - 잔여 노드에 대해 봉인 뷰의 각 dest_node별 깨끗한 최단경로 1개만 수집하여 비용순 정렬된 후보 목록 구성(비용 다양성은 dest_node 자체의 다양성으로 확보)
4. 조합 탐색은 앞쪽 구간 수에 따라 분기한다.
    - **앞쪽 구간 1개 (2-leg 총합):** 앞쪽 구간을 lazy iterate하면서 마지막 polygon leg의 정렬 배열을 bisect하여 잔여 예산에 가장 근접하는 직전·직후 후보를 결정. 종료: c_front + min(마지막 leg) − T ≥ best_diff, 또는 c_front가 T_j 상한 도달, 또는 K_MAX 도달, 또는 best_diff < 1e-4
    - **앞쪽 구간 2개 이상 (3-leg+ 총합):** 앞쪽 legs의 합산 비용이 작은 순서대로 min-heap으로 조합을 확장하고, 각 조합을 꺼낼 때마다 잔여 예산(T − c_front)에 대해 마지막 leg의 정렬 배열을 bisect하여 직전·직후 후보를 결정. 종료: c_front + min(마지막 leg) − T ≥ best_diff, 또는 best_diff < 1e-4

> 목적지 후보 노드 사전 필터링의 정당성: 최소 비용이 t_last를 초과하는 노드에서는 어떤 경로도 유효 상한 이내에 들어올 수 없으므로, 해당 노드를 제외해도 최적해에 영향을 주지 않는다.
> 

마지막 leg의 각 후보에는 `dst_node`가 포함되어 있어, 최종 선택 시 어떤 폴리곤 경계 노드가 목적지로 결정되었는지 역추적이 가능하다.

**[구간 모드] (`beg`·`end` 모두 입력) — 구간에 가장 부합하는 경계 지점 1개**

폴리곤 경계 지점(dest_node) 중 사료 거리대에 가장 부합하는 1개를 선택한다(`choose_target_interval_basic`). 각 dest_node의 총 metric을 기준으로, 1차로 구간거리 d = max(0, beg − m, m − end)가 최소인 지점을, 2차(구간 내 동률 시)로 구간 평균값 (beg + end)/2에 최근접인 지점을 선택한다. 구간 내 지점이 있으면 그중 평균 최근접을, 없으면 구간 최근접 지점(fallback)을 채택한다. abs_diff = max(0, beg − metric, metric − end)(구간 내부는 0).

> 구간 내 모든 경계 지점을 탐색하려면 순위 분석(`_순위.py`)을 사용한다.
>

## 5. 장애물 적용 구조 (공통)

포인트-포인트 분석과 포인트-폴리곤 분석 모두 동일한 장애물 적용 메커니즘을 사용한다.

- 장애물 유형: line (LineString / MultiLineString) 또는 polygon (Polygon / MultiPolygon)

- 장애물 미사용 시 원본 그래프를 그대로 사용

## 6. 경로 간 Jaccard 유사도 분석 (최소비용·영역제한)

### 목적

경로 분석 결과에서 route_target(목표값 근접 경로)을 기준선으로 두고, 각 route_min_*(임피던스별 최소 비용 경로) 및 장애물 적용 경로와의 공간적 유사도를 정량화한다. 이를 통해 사료에 기재된 거리에 부합하는 경로가 어떤 성격의 이동(거리 최소 / 시간 최소 / 에너지 최소, 군현 영역 제한 여부)에 가장 가까운지를 판별한다.

> 이 분석은 기본 분석(섹션 2·3)의 결과물(route_target + route_min_* 5개)을 입력으로 한다. 순위·편차범위 분석은 route_min_*를 생성하지 않으므로 본 분석의 입력으로 적합하지 않다.
> 

---

### 분석 원리

두 경로는 동일한 네트워크 그래프 위의 간선(edge) 순서열이다. 각 경로의 geometry 꼭짓점을 그래프 노드 좌표와 대조하여 간선 집합을 복원한 후, 길이 가중 Jaccard 유사도를 산출한다.

**길이 가중 Jaccard 유사도:**

J(A, B) = Σ length_3dkm(A ∩ B) / Σ length_3dkm(A ∪ B)

- 1.0 = 두 경로가 동일한 간선을 사용 (완전 일치)
- 0.0 = 공유 간선 없음 (완전 이탈)

간선 개수가 아닌 길이(km)로 가중하므로, 긴 공유 구간이 짧은 이탈 구간보다 유사도에 더 크게 기여한다.

### 간선 집합 복원 방법

GPKG에 저장된 경로 geometry는 간선 도형을 이어붙인 단일 LineString이다. 본 스크립트는 이 geometry의 꼭짓점 좌표를 graph_cache.pkl의 노드 좌표 집합과 대조하여 그래프 노드를 식별하고, 연속 노드쌍을 간선으로 복원한다. 노드 좌표는 EPSG:5179 기준 0.01 m(1 cm) 정밀도로 라운딩되어 있으므로 동일한 라운딩을 적용하면 정확히 매칭된다. 이 방식에 의해 경로 GPKG에 노드열을 별도 속성으로 저장할 필요 없이 기존 출력물만으로 분석이 가능하다.

**축약 그래프 대응 (`expand_chain_nodes`):**

그래프가 degree-2 체인 축약된 경우, 축약에 의해 제거된 중간 노드는 `G.nodes()`에 존재하지 않는다. 그러나 경로 분석 결과의 geometry에는 축약 전 원본 해상도(DEM 셀 크기 세그먼트)의 꼭짓점이 그대로 기록되어 있으므로, `G.nodes()`만으로는 geometry의 꼭짓점을 매칭할 수 없다.

이 문제를 해결하기 위해 `expand_chain_nodes(G)` 함수를 적용하여 다음 두 가지를 생성한다:

- `all_node_set`: `G.nodes()`에 각 축약 간선의 `chain_nodes`에 포함된 중간 노드를 추가한 전체 노드 집합. 비축약 그래프에서도 동일하게 작동(`chain_nodes` 미존재 시 [u, v]로 처리).
- `edge_length_lookup`: 원본 세그먼트 단위(연속 chain node 쌍)의 `length_3dkm` 딕셔너리. 예: `{(nodeA, nodeB): 0.03, ...}`

`geometry_to_edge_set`에 `all_node_set`을 전달하고, `weighted_jaccard`의 길이 조회에 `edge_length_lookup`을 사용함으로써, 축약 그래프에서도 원본 해상도의 간선 집합 복원과 길이 가중 Jaccard 산출이 정확히 작동한다.

> 이 구조는 비축약 그래프에 대해서도 하위 호환된다. `chain_nodes`가 없으면 [u, v]로, `chain_costs`가 없으면 간선의 `length_3dkm` 단일 값으로 처리한다.
>

## 7. 레이어 간 경로 구성 비교

### 목적

경로분석 결과물 간의 레이어 구성 차이를 속성 매칭 없이 비교한다. 경로 식별자(route_id)가 일치하지 않거나 피처 수 자체가 다른 경우에도 geometry 기반으로 구성 유사도를 산출할 수 있다.

---

### 비교 방식

두 GPKG의 단일 레이어를 각각 타겟·비교로 지정한다. 각 피처의 선형 geometry를 그래프 노드 좌표(0.01 m 라운딩)와 대조하여 간선 집합으로 변환한 후, 길이 가중 Jaccard 유사도를 산출한다. 축약 그래프인 경우 `expand_chain_nodes`를 적용하여 원본 해상도 노드 집합과 간선 길이 룩업을 생성한다(섹션 6 참조).

비교는 두 수준에서 수행된다.

- **레이어 전체 구성 비교:** 타겟·비교 레이어의 전체 간선 합집합(union edge set) 간 Jaccard, 공유 길이, 각 레이어 전용 길이, 피처 수 차이를 산출한다.
- **타겟 피처별 최유사 상대 탐색:** 타겟 레이어의 각 피처에 대해 비교 레이어의 모든 피처를 순회하며, Jaccard가 가장 높은 상대 1개를 선택한다.

속성 필드(route_id, weight_attr 등)는 비교 기준으로 사용하지 않는다. 피처 식별은 스크립트가 자동 부여하는 순번 ID(타겟: T_001, T_002, …; 비교: C_001, C_002, …)로 수행된다.

---

### 입력 요소

| 순서 | 파일 | 필수 | 설명 |
| --- | --- | --- | --- |
| 1 | graph_cache.pkl | ○ | 네트워크 그래프 캐시 (노드 좌표 매칭 및 간선 길이 참조) |
| 2 | 타겟 경로.gpkg | ○ | 비교의 기준이 되는 레이어 (GPKG 내 레이어 1개만 허용) |
| 3 | 비교 경로.gpkg | ○ | 타겟과 비교할 레이어 (GPKG 내 레이어 1개만 허용) |
| 4 | 출력 폴더 | ○ | CSV 저장 위치 |

---

### 전제 조건

- 입력 geometry는 경로분석 코드의 결과물(그래프 기반 생성)일 것
- 좌표계는 EPSG:5179 (이외 CRS는 자동 변환)
- geometry 유형: LineString 또는 MultiLineString
- 입력 GPKG에는 레이어가 정확히 1개만 포함될 것
- 속성 스키마가 달라도 비교 가능
- geometry의 꼭짓점 좌표가 그래프 노드 좌표와 일치하지 않는 경우 해당 구간은 간선으로 복원되지 않으며, 이 경우 해당 피처는 부분적으로 또는 완전히 비교에서 제외될 수 있다. 외부 편집된 선형, 좌표 미세 오차, vertex 단순화된 선형 등이 이에 해당한다.

## 8. 순위 분석 (목표값 근접/구간 상위 N위)

### 목적

기본 경로 분석(섹션 2, 3)이 목표값에 가장 가까운 단일 경로(rank 1)만 산출하는 데 비해, 순위 분석은 목표값 근접도/구간 적합도 상위 N개 경로를 모두 산출하여 단일 레이어에 출력한다. 이를 통해 사료가 지칭할 수 있는 경로의 후보 집합을 공간적으로 파악하고, rank 1 경로가 유일한 대안인지 복수의 대안이 존재하는지를 판별할 수 있다.

route_min_* 레이어는 생성하지 않으며, route_target 단일 레이어(`rank` 필드 포함)만 출력한다. 목표값 미입력(`beg` 빈칸) 행은 건너뛴다.

---

### 파라미터

| 파라미터 | 기본값 | 설명 |
| --- | --- | --- |
| TOP_N | 30 | 단일 모드 다양성 필터 통과 후 최종 출력 수 |
| TOP_N_INTERVAL | 30 | 구간 모드 최종 출력 수 |
| EMIT_N | 500 | 단일 모드 방출량 (다양성 필터 전 abs_diff 순 후보 수) |
| SIM_THRESHOLD | 0.95 | 다양성 필터: 이 값 이상이면 미세 변형으로 간주하여 제외 |
| K_MAX | 30,000 | 후보 생성 안전 상한 |
| K_PROBE | 300 | 2-leg 구간 모드 각 leg 기울기 측정용 짧은 열거 수 |
| PROBE_RATIO | 3.0 | 두 leg 기울기 비율이 이 값 이상이면 가파른 쪽을 bisect로 지정 |

---

### 내부 다양성 필터 (탐욕적 다양성 선택)

순위 분석은 후보 수집 후 **분석 스크립트 내부에서** 길이 가중 Jaccard 기반 다양성 필터를 직접 적용한다(별도 유사도 스크립트가 아님). 격자형 도로망에서는 상위 후보가 동일 도로 회랑 위의 미세 변형(한두 블록 우회 후 복귀)으로 채워지는 조합 폭발이 발생하므로, 이를 수집 단계에서 제거한다.

- 경로 노드열의 연속 노드쌍을 `frozenset((a, b))`로, 길이를 `G[a][b]["length_3dkm"]`로 읽어 간선 집합을 구성한다(`path_edge_set`).
- 길이 가중 Jaccard(`weighted_jaccard`)를 산출한다.
- 후보를 정렬 순서대로 검토하면서, 이미 선택된 모든 경로 대비 Jaccard가 모두 `SIM_THRESHOLD`(0.95) 미만이면 선택에 추가한다(`_passes_diversity`). 선택 수가 상한(TOP_N / TOP_N_INTERVAL)에 차면 종료한다.

> 이 탐욕적 선택에 의해 선택된 경로 간 상호 Jaccard가 0.95 미만임이 보장된다. 다양성 필터가 분석 스크립트로 통합되었으므로, 순위 결과(GPKG)는 이미 공간적으로 구별되는 경로만으로 구성된다.
>

### 알고리즘 개요

기본 분석(섹션 2, 3)의 탐색 엔진(T_j 상한 산출, K-shortest simple paths 열거, 봉인 기반 목적지 후보 탐색, 장애물 적용 등)을 그대로 사용하며, 행 형식에 따라 단일/구간 모드로 분기한다.

**[단일 목표값 모드] (`end` 빈칸, T = beg) — `choose_target_route_single_top_n`**

기본 분석의 목표값 근접 탐색을 "방출" 방식으로 확장한다. 목표값 근접(abs_diff 순) 후보를 충분히(`EMIT_N`=500) 수집한 뒤, 방출 결과에 다양성 필터를 적용하여 미세 변형을 제거하고 상위 TOP_N개를 출력한다.

- 1-leg(기점-종점)·2-leg(경유지 1개): abs_diff 순 상위 N이 정확하다(브루트포스 검증).
- 3-leg 이상(경유지 2개 이상): 방출 함수(`_top_n_three_plus_legs`)가 abs_diff 순 상위 N을 정확히 보장하지 못한다. 출력은 "목표값 근접 영역의 근사치 묶음"으로, 대체로 가까운 경로들이나 rank 경계에서 일부 후보가 정확한 순위와 어긋날 수 있다. **경유지 2개 이상 경로 분석 시 순위의 엄밀성에 주의한다.**
- T < S_min(목표값이 최단 경로보다 작은 경우): 모든 경로가 목표값보다 길어 최소 비용 경로가 곧 최근접 경로이며, 소수만 반환된다(정상 동작).

**[구간 모드] (`beg`·`end` 모두 입력) — `choose_target_route_interval`**

[beg, end] 범위 내 후보를 metric 오름차순으로 수집하면서 다양성 필터를 거치고, 상위 TOP_N_INTERVAL개를 선택한다. 구간 내 후보가 없으면 구간 최근접 1개를 fallback(rank 1)으로 반환한다.

- *단일 구간(경유지 없음):* K-shortest를 metric 오름차순 열거하며 `metric < beg`는 건너뛰고, `beg ≤ metric ≤ end`를 다양성 필터에 통과시키며, `metric > end`이면 종료(`collect_interval_single_leg`).
- *2-leg(경유지 1개):* T_j가 작은 leg을 bisect(사전 생성), 큰 leg을 lazy iterate로 할당하되, **probe 진단으로 역할을 동적 결정한다**(`collect_interval_two_legs`). 각 leg을 `K_PROBE`개만 짧게 열거해 metric 증가 기울기(후보 100개당 증가량)를 측정하고, 두 기울기 비율이 `PROBE_RATIO`(3.0) 이상이면 가파른(후보가 빨리 소진되는) leg을 bisect로 지정한다. 기울기가 유사하면 기존 T_j 규칙(작은 T_j를 bisect)으로 폴백한다. [beg, end] 범위 조합을 min-heap 병합으로 metric 오름차순 방출하며 다양성 필터를 거쳐 상위 N개를 선택한다(조합 전수를 누적하지 않음).
- *3-leg 이상(경유지 2개 이상):* 앞쪽 legs를 min-heap으로 조합 확장하고 마지막 leg을 bisect로 매칭한다(`collect_interval_three_plus`). 범위 조합을 min-heap 병합으로 metric 오름차순 방출하며 다양성 필터를 거친다.

**[포인트-폴리곤]**

폴리곤 분석은 위 구조에 봉인 기반 목적지 후보(섹션 3)를 결합한다. 마지막 polygon leg은 봉인 뷰에서 dest_node별 깨끗한 최단경로 1개씩을 수집하여 비용 다양성을 확보하고, 앞쪽 legs와의 조합을 단일/구간 모드 규칙으로 탐색한다. `t_last` 사전 필터링도 동일하게 적용된다.

## 9. 편차범위 분석 (목표값 ±margin 범위 내 상위 N위)

### 목적

사료의 거리 기록은 약 5리 단위의 반올림·올림·버림 관행이 있어, 입력된 목표값 자체에 ±5리(2.25 km)의 불확실성이 내재한다. 편차범위 분석은 이 불확실성을 명시적으로 반영하여, **입력 목표값(단일 T 또는 구간 [beg, end])을 margin만큼 확장한 구간 내에서** 목표값에 가장 가까운 상위 N개 경로만을 산출한다. 범위 밖 후보는 수집 단계에서 제외되므로 탐색 효율이 높고 결과의 해석 범위가 명확하다.

route_min_* 레이어는 생성하지 않으며, route_target 단일 레이어(`rank`·`margin` 필드 포함)만 출력한다. margin 범위 내 후보가 없는 경로는 출력에서 제외된다(fallback 없음).

---

### 파라미터

| 파라미터 | 기본값 | 설명 |
| --- | --- | --- |
| TOP_N_INTERVAL | 30 | 편차범위 최종 출력 수 |
| SIM_THRESHOLD | 0.95 | 다양성 필터: 이 값 이상이면 미세 변형으로 간주하여 제외 |
| K_MAX | 30,000 | 후보 생성 안전 상한 |
| MARGIN_KM | 2.25 | 거리 기반 편차범위 ±km (5리 × 0.45 km, 고정) |
| MARGIN_HR | 0.5 | 시간 기반 편차범위 ±hour 기본값 (실행 시 입력 가능) |
| K_PROBE | 300 | 2-leg 각 leg 기울기 측정용 짧은 열거 수 |
| PROBE_RATIO | 3.0 | 두 leg 기울기 비율이 이 값 이상이면 가파른 쪽을 bisect로 지정 |

---

### 입력 요소

기본 분석(섹션 2, 3)과 동일하다(`km_beg, km_end` / `hr_beg, hr_end`). 거리 기반 분석 시 margin은 ±2.25 km으로 자동 적용되며, 시간 기반 분석 시 실행 시점에 사용자가 margin 값(±hour, 기본 0.5)을 입력한다.

---

### 알고리즘 개요

편차범위 분석은 **입력 구간을 margin만큼 확장하여 순위 분석(섹션 8)의 구간 모드로 처리**하는 방식이다. 다양성 필터(SIM_THRESHOLD=0.95), probe 진단(K_PROBE·PROBE_RATIO), 구간 수에 따른 역할 분담은 순위 분석 구간 모드와 동일하며, 이하 차이점만 기술한다.

- **범위 확장:** 단일 목표값 T는 [T − margin, T + margin]으로, 구간 [beg, end]는 [beg − margin, end + margin]으로 확장한 뒤, 확장 구간에 드는 경로를 metric 오름차순으로 수집한다.
- **종료·필터:** metric이 확장 구간 상한을 초과하면 즉시 종료한다(비용 오름차순이므로 이후 후보는 모두 범위 밖). 확장 구간 내 후보만 다양성 필터를 거쳐 상위 TOP_N_INTERVAL개를 선택한다.
- **T_j 상한:** multi-leg의 T_j 상한은 확장 구간 상한 기준으로 산출하여 범위 상한까지 leg 후보를 허용한다.
- **fallback 없음:** margin 범위 내 후보가 없으면 해당 경로는 출력하지 않는다.
- **abs_diff는 원본 목표값 기준:** 단일은 |비용 − T|, 구간은 max(0, beg − 비용, 비용 − end)로 계산한다(margin 확장과 무관).
- **포인트-폴리곤:** 봉인 기반 목적지 후보(섹션 3)·`t_last` 사전 필터링을 확장 구간 상한 기준으로 적용하며, 나머지는 순위 분석 폴리곤 구조와 동일하다.

> [한계] 경유지 2개 이상(3-leg+)은 순위 분석과 동일하게 metric/abs_diff 순 상위 N의 엄밀성이 보장되지 않는 근사이며, rank 경계에서 어긋날 수 있다.
>

## 10. 순위/편차범위 경로 간 Jaccard 유사도 분석 (보조)

### 위상 변화 안내

순위·편차범위 분석(섹션 8·9)에 **탐욕적 다양성 선택 필터가 분석 스크립트 내부로 통합**되었으므로, 순위·편차범위 결과 GPKG는 이미 상호 Jaccard < 0.95인 경로만으로 구성된다. 따라서 아래 별도 유사도 스크립트(`경로_간_유사도_분석_순위.py`, `경로_간_유사도_분석_편차범위.py`)는 **이미 다양성이 확보된 결과에 대해 rank 간 유사도를 정량 산출·기록하는 보조 도구**의 위상을 가진다.

### 목적

순위·편차범위 분석 결과에서 rank 1(목표값 최근접/구간 최근접 경로)을 기준선으로 두고, rank 2 ~ rank N과의 길이 가중 Jaccard 유사도를 산출한다. 이를 통해 상위 순위 경로들이 동일한 도로 회랑을 공유하는지, 공간적으로 상이한 대안이 존재하는지를 정량적으로 판별한다.

### 분석 원리

간선 집합 복원 방법과 길이 가중 Jaccard 유사도 산출은 섹션 6과 동일하다. 축약 그래프인 경우 `expand_chain_nodes`를 적용하여 원본 해상도 노드 집합과 간선 길이 룩업을 생성한다(섹션 6 참조).

### 비교 구조

- 기준선(A): 각 route_id 내 rank 1 경로의 간선 집합
- 비교 대상(B): 동일 route_id 내 rank 2 ~ rank N 경로의 간선 집합
- route_id 내에서 rank 1이 존재하지 않는 경우 해당 route_id는 비교에서 제외

> 섹션 6(최소비용·영역제한)이 route_target과 route_min_* 간의 이종 레이어 비교인 데 비해, 본 분석은 동일 레이어(route_target) 내에서 rank 간 비교를 수행한다.
> 

### 입력 요소

| 순서 | 파일 | 필수 | 설명 |
| --- | --- | --- | --- |
| 1 | graph_cache.pkl | ○ | 네트워크 그래프 캐시 (노드 좌표 매칭 및 간선 길이 참조) |
| 2 | 경로_top.gpkg / 경로_top_margin.gpkg | ○ | 순위/편차범위 분석 결과 (route_target 레이어, route_id + rank 필드 필요) |
| 3 | 출력 폴더 | ○ | CSV 저장 위치 |

### 파라미터

| 파라미터 | 기본값 | 설명 |
| --- | --- | --- |
| SIMILARITY_THRESHOLD | 0.99 | 이 값 이상이면 미세 변형 경로로 간주하여 제외 |
| FILTER_TOP_N | 30 | 필터 후 유효 순위 최대 출력 수 |

> 유사도 스크립트는 다양성 선택 필터(이미 선택된 모든 경로 대비 Jaccard ≥ SIMILARITY_THRESHOLD 제외)를 적용하고, rank 1을 제외한 순위에 `filtered_rank`(1부터)를 부여하여 상위 FILTER_TOP_N개를 CSV로 출력한다. 필터 GPKG는 산출하지 않으며, 입력 GPKG를 그대로 시각화 대상으로 사용한다.
> 

### 출력 결과

**CSV** — `유사도_순위.csv` / `유사도_편차범위.csv` (long format, 필터 통과 rank별 1행)

| 컬럼 | 정의 |
| --- | --- |
| route_id | 경로 식별자 |
| filtered_rank | 필터 후 순위 (1 = 임계값 미만 첫 번째 rank) |
| original_rank | 원본 순위 (GPKG의 rank 필드와 대응) |
| jaccard | rank 1 vs 해당 rank의 길이 가중 Jaccard (0–1) |

> rank 1만 존재하거나, 전체 rank가 기선택 경로와의 임계값을 통과하지 못하는 route_id는 CSV에서 제외되며, 해당 건수가 콘솔에 보고된다. 편차범위는 margin 범위 내 rank 1만 존재하는 경우와 임계값 미통과 경우를 구분 보고한다.
> 

### 결과 해석

- 필터 후 유효 rank가 없는 route_id: 상위 대안 경로들이 모두 rank 1의 미세 변형이거나 rank 1만 존재하며, 공간적으로 구별되는 대안이 없다. 경로 추정의 신뢰도가 가장 높다.
- filtered_rank가 존재하나 Jaccard가 0.5 이상으로 유지: 대안 경로가 존재하지만 rank 1과 상당 부분을 공유한다.
- filtered_rank 1부터 Jaccard가 낮은 경우(0.5 미만): rank 1과 공간적으로 상이한 대안이 즉시 존재하여, 사료의 거리 기록만으로는 경로를 단일하게 특정하기 어렵다.
- 편차범위 유사도는 "사료 기록 불확실성 범위 내에서 공간적 대안이 존재하는가"를, 순위 유사도는 "목표값 근접 경로 간 공간적 유사성"을 측정한다. 두 결과를 병치하면 margin 범위 제약이 경로 다양성에 미치는 영향을 정량 비교할 수 있다.

### 스크립트

- 순위: `경로_간_유사도_분석_순위.py`
- 편차범위: `경로_간_유사도_분석_편차범위.py`

## 12. 실행 로그 체계

6개 경로 분석 스크립트(`경로분석_point_point*.py`, `경로분석_point_polygon*.py`)는 실행 중 콘솔에 진행 상황을 표준 라벨 체계로 출력한다. 로그는 분석 진입·분기·단계를 안내하는 1회성 **구조 로그**와 장시간 반복 루프의 진행 상황을 주기적으로 알리는 **주기 로그**로 구성된다. 주기는 루프 내 반복당 연산 비용에 반비례하여 설정된다.

### 라벨 체계

| 라벨 | 층위 | 주기 | 발생 위치 | 비고 |
| --- | --- | --- | --- | --- |
| `[barrier]` | 구조 | 1회 | `apply_barrier_edges` | — |
| `[skip]` | 구조 | 행별 1회 | CSV 행 오류 보고 | `end`만 입력(`beg` 누락), `beg > end` 행 건너뜀. 전 스크립트 공통 |
